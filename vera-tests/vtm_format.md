# VTM — Vera Tracker Module (v2)

A compact PSG-only music format for the VERA PBI card, played back by
`vtm_player.s`. Drives 4 of VERA's 16 PSG (wavetable) voices under vertical
blank timing — no PCM, no effects column, on purpose: the player asm stays
tiny and the timing loop trivial.

Songs are authored in a small text language (see `vtm_compile.py`) and
compiled to this binary layout. The whole file is loaded into RAM as one
blob and addressed with 16-bit offsets from its own start — no relocation.

## Header (12 bytes)

| Offset | Size | Field            | Notes                                    |
|-------:|-----:|------------------|-------------------------------------------|
| 0      | 4    | magic            | `"VTM2"`                                  |
| 4      | 1    | n_channels       | fixed at 4 for v1, player validates it    |
| 5      | 1    | frames_per_row   | VBI frames per row (tempo); >= 1          |
| 6      | 1    | n_instruments    |                                            |
| 7      | 1    | n_patterns       |                                            |
| 8      | 1    | order_len        |                                            |
| 9      | 1    | loop_pos         | index into order[] to jump back to at end |
| 10     | 2    | reserved         | 0                                          |

Followed by, back to back:

- `order[order_len]` — 1 byte each, pattern index per song position.
- `instruments[n_instruments]` — 3 bytes each (see below).
- `pattern_table[n_patterns]` — 3 bytes each: `n_rows` (1 byte),
  `data_offset` (2 bytes, little-endian, absolute offset from file start).
- pattern cell data, concatenated, pointed to by `pattern_table[].data_offset`.

## Instrument (3 bytes)

The first two bytes map directly onto VERA PSG registers 2 and 3 — the PSG
itself has no envelope hardware, so byte 2 is a decay rate applied in
software by the player, not a VERA register:

- byte 0 (reg2): bit7=R, bit6=L, bits5:0 = volume (0-63)
- byte 1 (reg3): bits7:2 = pulse width (0-63), bits1:0 = waveform
  (0=pulse, 1=sawtooth, 2=triangle, 3=noise)
- byte 2 (decay): amount subtracted from the volume every VBI frame after
  note-on, clamped at 0. `0` = sustain (flat volume, no envelope — use for
  pads/leads/bass). A nonzero value makes the voice decay to silence in
  roughly `volume / decay` frames, independent of tempo — use a fast decay
  (e.g. 8-20) for percussive instruments (hats, kicks) so they tick instead
  of buzzing. Decay is re-triggered (volume reset to the instrument's byte
  0) on every note-on; note-off silences immediately regardless of decay.

## Pattern cell (2 bytes per channel per row)

- byte 0 — note:
  - `0` = hold (no event this row, previous note keeps sustaining)
  - `1..96` = note-on, note index = byte-1 (0 = C-0 .. 95 = B-7)
  - `97` = note-off (silences the channel: writes volume=0)
  - other values reserved
- byte 1 — instrument index, or `$FF` to keep the channel's current
  instrument. Only consulted on note-on; ignored for hold/note-off.

Row layout within a pattern is channel-major-per-row, i.e. row 0's 4 cells,
then row 1's 4 cells, etc — `n_rows * 4 * 2` bytes total.

## Playback model

One shared order list drives all 4 channels in lockstep (classic
tracker/RMT style): the song plays pattern `order[order_idx]` for its
`n_rows` rows, advancing one row every `frames_per_row` VBI frames, then
moves to `order[order_idx+1]`, wrapping to `order[loop_pos]` after the last
entry. Individual channels sustain across rows via `hold` and are cut with
an explicit note-off — there is no separate "note duration" field, duration
is however many hold rows follow a note-on, at the tempo set by
`frames_per_row`.

## Implementation limits

The player indexes `order[]`, `instruments[]` and `pattern_table[]` with a
single 6502 Y register, so: at most 255 order entries, at most ~85
instruments (idx*3 must stay <= 255), at most ~85 patterns (idx*3 must stay
<= 255). Comfortably beyond what a hand-authored tracker song needs.

## Note frequency table

`vtm_notes.inc` (generated by `tools/gen_note_table.py`) holds a 96-entry
table of VERA PSG frequency words, equal temperament, A-4 = 440 Hz = word
1181 (matches the worked example in the VERA Programmer's Reference).
Regenerate only if the note range or tuning changes — the values are pure
hardware constants otherwise.
